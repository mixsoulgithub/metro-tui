# metro-tui

终端里的地铁线路图。用 `ratatui` + `crossterm` 画成 **ASCII / 箱线字符**的地图,一条线路一种
24 位真彩颜色;站序和坐标来自人工整理的站序表与 OpenStreetMap,同一份数据有**示意图**和
**真实地理**两种画法。

## 特性

- **两种画法**:示意图(放松布局,横竖斜吸附)与真实地理(等距圆柱投影),`r` 一键切换;
- **站序就是数据**:`J L` 下一站、`H K` 上一站,只按线路自己的站序走,和屏幕方向、真实方位都无关;
- **方向键按屏幕几何**:挑那个方向上"最近且正对着"的站(分数 = 屏幕距离 + 2 倍横向偏斜);
- **搜索**:中文、拼音(`wulin`)、首字母(`wlgc`)、线路号(`/1` 高亮整条线);
- **鼠标**:左键点站、按住拖动平移、滚轮缩放、`Ctrl`+滚轮上下平移;
- **多城市**:启动列出所有现成的线路图,`--city <slug>` 直接进;加城市不用重新编译;
- **无头渲染**:`--dump` 输出一帧真彩 ANSI,方便截图、回归比对;
- 只依赖 `ratatui` / `crossterm` / `unicode-width`,没有网络和数据库依赖。

## 构建与运行

需要 Rust(edition 2021)和一个支持真彩与 UTF-8 的类 Unix 终端。

```bash
git clone git@github.com:mixsoulgithub/metro-tui.git
cd metro-tui
cargo build --release
./target/release/metro               # 先出选城市界面
./target/release/metro --city chengdu
```

终端别太小:整幅图 97 km x 51.5 km,200x50 左右正好用满。

## 命令行

```
metro [options]
  --city <slug>  直接进某座城市(如 hangzhou / shanghai / chengdu / shenzhen)
  --file <path>  读取线路图 .dot
  --dump         渲染一帧到 stdout(真彩 ANSI)后退出,可配合 --size
  --size <WxH>   --dump 的画布大小(默认 200x50)
  --labels       一上来就把所有站名标出来(等于按 b)
  --real         按真实经纬度画(默认是示意图,按 r 可以随时切)
  --at <站名>    开局把光标停在那一站
  --find <词>    开局就搜一遍(站名/拼音/首字母,或线路号)
  -h, --help     显示帮助
```

`--dump` 是纯文本输出,直接 `less -R` 看,或者重定向成文件:

```bash
./target/release/metro --dump --size 220x55 | less -R
```

## 键位

| 键 | 作用 |
| --- | --- |
| `h` `j` `k` `l` / 方向键 | 朝那个方向挑**离得近、而且方向正对着的那一站**(分数 = 屏幕距离 + 2 倍横向偏斜,所以不会挑到斜着挨着的那一站):距离和方向都按屏幕格子算 —— 眼睛看到哪站在那个方向、哪站近就走哪站,所以换个终端尺寸、或者切到示意图/真实视图,答案都可能不同;那个方向 45 度锥形以外的站不算。聚焦某条线时(`/1` 或 `V`)那条线上的站容忍更多距离,方向键基本就在沿那条线走(强度可用 `:cycle` 调) |
| `H` `K` / `J` `L` | 沿线走一站:**`H` `K` 是上一站,`J` `L` 是下一站** —— 只按线路自己的站序,和真实方位、屏幕方向都无关(换乘站上按 `H` 就是这条线的上一站,不会拐到别的线)。站上同时有好几条线都能走时弹一个列表:数字或 `j` `k` 选、回车走、`esc` 取消 |
| `+` `-` | 放大 / 缩小 |
| `0` | 复位成整幅图(缩放和位置一起复位) |
| `空格` `z` | 把光标那一站挪到画面正中(平滑滑过去) |
| `f` | 把聚焦的线路(没聚焦就是当前站那条线)整条铺满画面 |
| `b` | 开关站名标注 |
| `/` | 搜站名 / 拼音 / 首字母(比如 `wulin`、`wlgc`);输入纯数字则高亮那条线的全部车站 |
| `5l` `3j` | 数字前缀:一次性挪好几站(纯键盘长途旅行用) |
| `Ctrl-d` `Ctrl-u` | 半屏往下 / 往上跳一站(比一站一站按快得多) |
| `Ctrl-o` `Ctrl-i` | 回到上一个 / 下一个"跳过的站"(搜索、鼠标点、半屏跳都会记进去;`Tab` 就是 `Ctrl-i`) |
| `n` `N` | 下一个 / 上一个命中的站 |
| `V` | 聚焦当前站所在的线路(换乘站一次聚焦几条,和搜这几条线的线路号一个效果,之后按 `n` 能一站站看过去);这一站的线已经在聚焦里,这一下就是取消 |
| `r` | 在示意图与真实地理之间切换 |
| `?` | 键位速查浮层(任意键关掉) |
| `:` | 命令行(调试):`:cycle <倍数>` 同线那一档允许比最近的远多少;`:side <倍数>` 横向偏斜算几倍距离(调小就更认"屏幕上最近");`:cycle auto` 回到默认 |
| 鼠标 | 左键单击跳站;左键按住拖动平移地图;滚轮缩放;`Ctrl`+滚轮上下平移(`Shift` 左右)。在 tmux 里跑要 `set -g mouse on`,不然鼠标事件到不了程序 |
| `q` / `esc` | 回到选城市界面(`--city` 进来也一样);在选城市界面里按才退出 |

选城市界面里也是 `j` `k` 选择、回车打开、数字直选,列表长了会滚动。

当前那一站是**实心**的(普通站 `●`、换乘站 `◉` —— 图上其它站是空心 `○` `◎`),
颜色在亮白和红色之间来回闪:曲线是**正弦**,**节奏按心跳的频率**(一个来回 0.8 秒,约 75 下/分),
所以一眼就能找到"我在这儿"。闲着时按 ~30fps 重画(移动中 60fps)。

移动是平滑的:视图中心每帧朝目标挪掉剩余距离的 22%,到位后吸附到不足半格,所以按 `空格` 居中
或者方向键把光标带出视野时,画面是滑过去的;`0` 复位和 `+` `-` 缩放立即生效。

## 两种画法

默认是**示意图**:从真实经纬度出发做放松,让每条线上的相邻站间距差不多,线的走向吸附到横、竖、
45 度上,同时把站点互相推开至少一格 —— 排出来的疏密像一张地铁线路图,不会有市中心挤成一团、
或者一条大站快线拉出十公里直线的情况。相对方位仍然是真实的:临安在西北、萧山机场在东南、
富阳支线往西南、大江东往东。

`--real`(或按 `r`)切到**真实地理**:按等距圆柱投影直接从经纬度落图,纵向按"字符格高约等于宽的
两倍"修正。站密的地方会挤在一起,长站距的大站快线会拉出很长的直线,但位置就是实际位置。

两种画法都不做"哪些站可达"的高亮 —— 图上哪儿都能去。绘制规则:

- 普通站 `○`,换乘站 `◎`(白色加粗),颜色都是那条线的颜色;
- 线路是正交走线:只用 `─` `│` 两种笔画,拐弯处 `╭` `╮` `╯` `╰`(和 lazygit 的提交图一个路子);
- 两条线在**非站点处**交叉 = 一条从另一条下面过:占住那一格的那条线照自己的形状画,另一条在这一格
  断一格。所以 `├` `┤` `┬` `┴` `┼` 基本只会出现在站点上,图上不会有"看着像换乘、其实什么都没有"的十字;
- 每条边要么直连,要么拐一个直角。拐哪一边先看这一站在整条线上是"竖着进"还是"横着进"
  (前后两站都在它北边/南边就竖着进),于是"下去再上来"这种折返会走**同一列**,不会绕出方框;
  再不然才看哪种拐法踩到的**别的线**的格子少;
- 一格只能有一种颜色。冲突时**光标所在站的线路优先**:两条线的笔画撞在同一格、或者一个换乘站连了
  多条线,颜色都让给光标那条线 —— 沿线走的时候顺着颜色就能把自己这条线整条连起来看;
- 端点站常驻站名;窗口大到站距在屏幕上拉开 4 格以上会自动标所有放得下的站名,`b` 可强制全标。

## 布局是怎么排的

`src/layout.rs` 是一遍**确定性**的放松(没有随机数),从真实坐标出发:

1. 先把经纬度铺进 192x48 的格子当初始位置;
2. 每轮迭代四件事:相邻站之间的弹簧(目标间距 2.6 格)、方向吸附(把每条边掰向横、竖或 45 度)、
   把"一条线上连着三站"往共线拽(中间站是**按线路**算的 —— 换乘站对每条经过它的线都是中间站)、
   站点之间的斥力,再叠一个跟着布局一起缩放的"锚",只负责保住相对方位;
3. 600 轮之后取整到格子:一格一站,占了就按同心环往外找最近的空格;
4. 收尾反复做三件事直到都改不动:把边掰直、把相邻站拉开、把**任意**两站分开至少一格;
5. 规格留一点余量:200x50 的窗口下整幅图是"放大"铺满的,而不是被压着塞进去。

规格固定成 192x48,换窗口只是把同一张图放大缩小,图本身不会跳。

## 数据

### 站序表 → .dot

```
docs/hangzhou-subway.md     线路与站点顺序(人工整理)
      |  tools/md2dot.py    站名去 OSM 找真实坐标,缺失的按线路顺序插值
      v
docs/hangzhou-subway.dot    站点(带 pos)+ 相邻站之间的边(带线路色)
      |  include_str!       编译进程序(或者放用户数据目录,启动时扫描)
      v
src/dot.rs -> src/map.rs -> src/ui.rs   投影 + 绘制
```

上海 / 成都 / 深圳是"线路,站名,经度,纬度"的 csv(一行一站,一条线路一个块),一个命令出图:

```
tools/csv2dot.py --city shanghai     docs/shanghai-subway.md -> docs/shanghai-subway.dot
tools/csv2dot.py --all               全部有站序表的城市
```

块里的站序就是线路上的顺序;换乘站在多块里重复出现,按站名并成一个节点。支线可以单独成块
(推荐)、也可以写在主线块里(按几何认出岔口接回去);认不出来又长得离谱的会丢掉那条边并打印出来 ——
与其画一条横贯全图的假线,不如留个缺口让人去核对。线路颜色能从 OSM 的 `colour` 标签拿到就用真的,
没有就按序号取调色板。

杭州那条链路走 `tools/md2dot.py`:站名去 `data/osm_stations.json` 里查坐标(同名多个就取离这条线
最近的),一条线的 OSM 关系按 150 米并成一张 stop 图,文档里相邻的两站在图上走最短路、路上经过的
站会补进来;OSM 缺的端点站用站点节点自己的坐标,再缺就按线路顺序插值。想重抓:

```bash
python3 tools/fetch_osm.py     # 写 data/osm_routes.json + data/osm_stations.json
python3 tools/md2dot.py        # 重新生成 docs/hangzhou-subway.dot
cargo build --release          # dot 是 include_str! 进来的,要重编
```

### 从 OSM 生成任意城市

```
tools/fetch_city.py --city shanghai   抓 OSM 原始数据
tools/osm2dot.py    --city shanghai   关系里 stop 成员的顺序就是站序 -> dot
```

加新城市只改一处:`tools/cities.py` 里的表(slug / 中文名 / OSM 的 network 标签 / bbox),
`networks` 留空表示"bbox 内的 `route=subway` 关系全要"(不对运营方打标签的地区常用)。

```
python3 tools/build_cities.py --all              # 一条命令批量建:抓 OSM -> 生成 dot(断点续跑)
python3 tools/build_cities.py --city wuhan       # 只建某几座
python3 tools/build_cities.py --all --done list  # list 里列出的城市跳过(一行一个 slug)
```

Overpass 时通时断:脚本启动时先探一遍几个镜像,只留能应答的,之后失败的查询换镜像、退避重试;
站点优先按线路 stop 成员的节点 id 取(走索引的小查询),整城查只作兜底;抓到的分格有缓存,
断了重跑不白干。本机有代理就直接给环境变量(脚本走 urllib,会自动识别):

```fish
set -x https_proxy http://127.0.0.1:<端口>
python3 tools/build_cities.py --all
```

建好的 `.dot` **不用重新编译**:程序启动时会扫描仓库 `docs/` 和用户数据目录
(`$XDG_DATA_HOME/metro/cities`,默认 `~/.local/share/metro/cities`)里现成的线路图,
`--city <slug>` 也能直接打开。想固定进二进制,就在 `src/city.rs` 的 `CITIES` 里加一行 `include_str!`。

拼音表用 pypinyin 的字典筛出用到的字,落在 `data/pinyin_chars.txt`;改了城市之后跑
`tools/fetch_pinyin.py` 重新生成,`--extra-dir <目录>` 可以再把别的目录(及其子目录里的
`.md`/`.dot`)一块儿扫进来,`-o` 指定写到哪。

### 数据来源与许可

- 站点坐标、线路颜色:OpenStreetMap 的 `route=subway` 关系与 `station=subway` 节点,
  (c) OpenStreetMap contributors,**ODbL** 许可;
- 线路与站点顺序:仓库里那四座城市来自 `docs/` 下人工整理的站序表(上海 / 成都 / 深圳 的
  坐标顺序取自同一批 OSM 关系里 stop 成员的顺序);
- 拼音表取自 [pypinyin](https://github.com/mozillazg/python-pinyin) 的字典(MIT)。

## 已知取舍

- 一条线自己画的笔画不该围出空格(视觉上就是个方框)。路由上有两条约束:折线不从**别的站点**上穿
  过去;拐弯时也不许把自己绕成环。杭州 2 号线还有 1 处、9 号线还有 2 处小圈,是最后一段"直线"
  封的口(直线段没有拐法可选),要彻底消掉得做全局重排。
- 市中心站距常常不到一格,缩到最小会挤在一起;`+` 放大看局部,或者把窗口开大。
- 换乘站里如果有几条线各有一个自己的站体,OSM 上是不同节点,这里按"同名且在线附近"合并成一个。
- 用 `#` 表达换乘站后,原本经过它的线路颜色在那一点会断开,这是终端一格一色的限制。
- `○` `◎` `─` 这些字符的东亚宽度是"不确定"(ambiguous):宽字符终端 + CJK 字体会把它们画成两格宽,
  那样整幅图会错位。用等宽字体、locale 不是 CJK 的终端就没问题。
